An import is not "load file"; it's an ETL job where the hard part is **linking**:

## 1. The Excel importer (your workhorse for foreground data)

`bw2io.ExcelImporter` reads a structured workbook (one this repo provides at
[data/kettle_import.xlsx](../data/kettle_import.xlsx), generated by the
notebook). Layout essentials:

```
Database    kettle_xl          â† database block header
                                 (blank row)
Activity    electricity production, coal   â† one block per activity
unit        kilowatt hour
type        process            â† REQUIRED â€” see gotcha below
Exchanges                      â† then a header row + one row per exchange
name                     amount   unit            database     type        categories
electricity productionâ€¦  1.0      kilowatt hour   kettle_xl    production
Carbon dioxide, fossil   0.95     kilogram        biosphere3   biosphere   air
```

> **The #1 Excel-import gotcha:** every `Activity` block must carry an explicit
> `type   process` row. Without it, the importer cannot link the activity's own
> self-referencing `production` edge, and `statistics()` reports *every* activity
> as unlinked (production + technosphere edges all fail). Add `type: process` and
> the same file links cleanly to zero unlinked. Also: the importer **reassigns
> codes to activity hashes**, so after writing, look activities up by `name`
> (`bd.get_node(database=..., name="kettle assembly")`), not by a code you chose.

Then:

```python
imp = bw2io.ExcelImporter("data/kettle_import.xlsx")
imp.apply_strategies()                     # normalize units, names, formats
imp.match_database(fields=["name"])        # link internal exchanges
imp.match_database("biosphere3",
                   fields=["name", "categories"])   # link elementary flows
imp.statistics()                           # X datasets, Y exchanges, Z unlinked
```
